# pixel-factory-to-ota

`pixel-factory-to-ota` converts Google Pixel factory images into a full Android A/B OTA update package. This is intended for users who run custom-signed versions of the Pixel stock OS, especially for Android channels where Google does not provide full block-based OTAs (such as Android Canary).

> [!IMPORTANT]
> OTAs generated by this tool **cannot be flashed as-is** and **must** subsequently be re-signed and patched with [`avbroot`](https://github.com/chenxiaolong/avbroot).

---

## Architecture & Workflow

```text
Pixel factory ZIP (-i)
       │
       ▼
Find nested uncompressed image-*.zip (streamed in-place via BoundedReader)
       │
       ├── Extract super_empty.img -> super/
       └── Extract payload partition images -> ota/payload_images/
       │
       ▼
avbroot lp unpack -q -i super_empty.img -> super/lp.toml
       │
       ▼
Determine dynamic partition group and partitions (stripping '_a' slot suffixes)
       │
       ▼
afsr unpack each dynamic partition -> filesystems/<name>/fs_tree
       │
       ├── Parse build.prop for system, vendor, and dynamic partitions
       └── Discover APEX/CAPEX packages, unpack original_apex size, and decode apex_manifest.pb
       │
       ▼
Generate metadata artifacts:
       ├── ota/payload.toml (VABC LZ4 cow v3, block size 4096, postinstall hooks)
       ├── ota/ota.toml (A/B OTA metadata, pre/post device states, timestamps)
       └── ota/ota_files/apex_info.pb (binary protobuf representation of ApexMetadata)
       │
       ▼
Generate ephemeral RSA-4096 signing keypair (ota.key & ota.crt) via avbroot
       │
       ▼
avbroot avb verify -i payload_images/vbmeta.img
       │
       ▼
avbroot zip pack -q -o <output.zip> -k ota.key -c ota.crt --payload (cwd: ota/)
       │
       ▼
Generated A/B OTA ZIP (-o)
```

## Prerequisites

1. **Rust Toolchain**: Rust 1.88+ (tested and verified with Rust 1.98.1 2024 edition).
2. **Protocol Buffers Compiler**: `protoc` (3.x or 20+).
3. **External Tools**: The following executables must be present in `PATH`:
   - [`avbroot`](https://github.com/chenxiaolong/avbroot) (>= 3.34)
   - [`afsr`](https://github.com/chenxiaolong/afsr) (>= 1.0)

## Installation & Building

Clone the repository and compile using Cargo:

```bash
cargo build --release
```

The resulting binary will be located at `target/release/pixel-factory-to-ota`.

To install into your user Cargo binary directory (`~/.cargo/bin`):

```bash
cargo install --path .
```

## Usage

```text
Usage: pixel-factory-to-ota [OPTIONS] --input <INPUT> --output <OUTPUT>

Options:
  -i, --input <INPUT>        Input factory image
  -o, --output <OUTPUT>      Output OTA
  -w, --work-dir <WORK_DIR>  Working directory (for debugging)
  -h, --help                 Print help
```

### Basic Example

```bash
pixel-factory-to-ota -i pixel-factory.zip -o ota.zip
```

### Debugging with a Persistent Working Directory

To inspect intermediate artifacts (partition images, extracted filesystem trees, generated TOML files, and keys):

```bash
pixel-factory-to-ota \
    -i pixel-factory.zip \
    -o ota.zip \
    -w ./debug-work-dir/
```

When `--work-dir` is provided, intermediate artifacts are retained. If `--work-dir` is omitted, an ephemeral secure temporary directory is automatically created and cleaned up upon exit.

### Temporary Storage Considerations

Processing full factory images requires significant temporary disk space (typically 15–30 GB depending on device and partition count). If your default `/tmp` directory has insufficient space or is mounted on `tmpfs` (RAM), set the temporary directory environment variable:

- **Linux / macOS**: `export TMPDIR=/path/to/large/disk`
- **Windows**: `set TEMP=D:\Temp`

## Development & Testing

Run the test suite:

```bash
# Run unit tests, CLI tests, fixture tests, and integration tests
cargo test

# Check code formatting
cargo fmt --check

# Run Clippy lints with -D warnings
cargo clippy --all-targets --all-features -- -D warnings
```

### Test Hierarchy

- **Unit Tests**: Bounded stream reader with seek semantics and bounds validation, `build.prop` key/value parsing, partition name sanitization, and APEX inspection.
- **Fixture Tests**: TOML serialization and deserialization against `avbroot` schemas, protobuf message encoding and decoding.
- **Integration Tests**: End-to-end OTA creation with synthetic factory image archives using `mke2fs`, `lpmake`, and `avbroot`.
- **Differential Parity Tests**: Automated test suite that executes both the reference Python implementation and the Rust implementation on identical inputs, asserting strict semantic equality of `payload.toml`, `ota.toml`, `apex_info.pb`, and output ZIP archive structures.
